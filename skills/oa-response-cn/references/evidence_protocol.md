# 案卷证据与来源分层规范（v0.2）

## 引用证据前的最小闭环
每一个有争议的创造性论点必须分别记录：
- **权项原文**：版本、权项号、连续原文、对应分句。
- **OA观点**：OA轮次、页码、审查员对应该特征的原话/不失真摘录。
- **D1—Dn原文**：公开号、页码或段落、附图、实际公开的数据对象/处理步骤/用途；不能以别案复述替代。
- **原始申请支持**：说明书段落/附图/原权项、原文关键部分；“新增特征已存在”与“多个特征组合有依据”分开核查。
- **解释与推断**：将“原文记载”“合理推导”“代理策略性主张”三个层次分开。

## 证据标注标签
`[原文已核]`：已直接读取原文并给出位置；`[OA主张]`：审查员观点，未必等于实际公开；`[推断]`：基于事实作出的逻辑结论；`[未检索到]`：已检索但不能替代绝对未公开；`[待核]`：无法读取或来源不完整；`[用户确认]`：用户选择的策略/权要。

## 禁止
- 禁止编造`[0073]`等貌似精确段号、给未读文件编页码、将“OA引用”表述成“原文验证”。
- 禁止自动更改“第1”“第m”等关键技术术语或数值上下限以让技术链看起来合理。
- 不将用户附带的旧案联系信息、权项总数、日期复制到新案。
- 引用法律时注明具体法规名称、年份/修订版、条号与当前适用性；未核对时明确“不确定”。

## 主张记录（每条）
```yaml
id: ARG-01
claim_version: 当前有效/拟修改/已确认最终
claim_text: 权利要求原文
examiner: 通知书页码及观点
references:
  D1: 公开号 + 段号/附图 + 精确内容
  D2: 公开号 + 段号/附图 + 精确内容
application_basis: 原申请位置与原文
fact_status: 原文已核 / OA主张 / 待核
reasoning: 相同点、不同点及其技术作用
counterargument: 最强可预见反驳
strategy: 主论点 / 辅论点 / 不采用
```
