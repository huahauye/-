# oa-response-cn v0.2 | 中国发明专利OA答复工作流

## 目标和边界
- 目标是为专业代理工作提供 **证据可追溯、程序有闸门、可版本化** 的OA分析与答复。不是以模板词堆砌“具有创造性”，不能承诺授权率/授权结论，也不能代替有资格人员签署或提交。
- 优先顺序：当次OA与原申请/有效权利要求/引证全文的可核事实、当时适用法规 → 用户确认的策略与风格 → 案例中的可迁移方法。任何案例结论不能直接套到新案。
- 技术、版本、法律事项都要有来源；没有可核查的文件/段落必须标记“待核实”，**绝不可虚构引证段号、说明书依据、技术效果、官方期限**。
- 法律依据及生效时间按 `references/legal_sources.md` 在每个新案重新核对。尤其注意2026年起生效的《专利审查指南》修订和过渡适用。

## 工作流（按用户明确要求可仅执行部分阶段）

### 阶段0 | 材料接收与版本锁定（默认从这里开始）
读取 `references/intake_workflow.md` 和 `references/evidence_protocol.md`。
- 清单：本次OA全文、原始申请及公布/公开文本、当前有效权要、前次OA/答复/修改对照、D1—Dn全文、案卷必要日期、拟答复期限；检查正文、表格、附图及PDF是否为可提取文本/扫描件。
- 区分 **原始提交版本 / 当前有效版本 / 内部候选版本 / 经用户确认的最终替换页**。有缺失或冲突立即报告，不能按文件名推定内容；不能因为意见陈述书提到某权项总数就视为已验证完整权要。
- 交付“材料核验表 + 缺失项 + 版本台账”；用户确认后进行分析。若用户已经明确提供本阶段已确认的信息，不重复机械询问。

### 阶段1 | 审查意见和证据链重建
- 逐条摘录**审查员实际观点**、指向权项、适用法条、文献组合及原文页码；涉及OA2/多通，建立本次和上次的争议演变表。
- 按 **最新有效权利要求原文** 分割技术特征；制作逐特征矩阵，针对D1—Dn标注“明示 / 必然隐含 / 被审查员主张但尚待核实 / 未见公开 / 无法读取”。“未检索到”不能偷换为绝对“未公开”。
- 先核对每份引证的法律地位、时间属性与适用场景；抵触申请和创造性现有技术不混淆。

### 阶段2 | 创造性策略与候选方案
阅读 `references/mairui_decision_tree.md`、`references/creativity_framework.md`、`references/examiner_counterattack.md`。
- 先执行 P0时间资格→P1区别特征→P2客观技术问题；P3 D1改进动机/P4其他文献技术启示/P5组合障碍/P6公知常识作为可并行论点，不是必须使用全部论点。
- 创造性三步法：最接近现有技术→区别特征及有根据的实际效果→客观技术问题→是否存在能实现**完整技术方案**的技术启示与合理组合路径。诚实承认文献已公开内容。
- 优先提出“不修改争辩 / 较小限缩 / 有依据的增强限缩”中的可行策略；**不强制凑满三种**。每种写原文来源、技术作用、保护范围影响、创造性强弱和可能的二次攻击。用户确认答复方向后继续。

### 阶段3 | 权利要求修改与依据
阅读 `references/claim_amendment.md`。
- 分别列明原权项/现权项/拟修改权项；生成完整修改稿、逐项修改对照、原始申请支持位置、组合支持、保护范围牺牲及修改超范围/清楚性/引用关系风险。
- 原文没有支持的关系不能补造；出现别扭但忠于原始记载的表达，不得擅自改造成看似更合理的技术方案；提示人工判断。
- **必须得到用户对拟修改权项文字及方案的明确确认** 才能进入正式起草。

### 阶段4 | 创造性框架、反向攻击与正式正文
- 先交付“最接近现有技术—区别技术特征原文—效果和依据—实际解决问题—D1+D2/Dn技术启示—审查员可能反驳—证据风险”；确认后使用 `references/oa_writing_style.md`、`assets/opinion_body_outline.md` 撰写。
- 每个区别特征保持**修改后权利要求逐字引用**，正文针对审查员核心观点逐项回应；“突出实质性特点”“显著的进步”分别有论据，篇幅服从证据价值。
- 只有OA涉及该事项才写新颖性/支持性/清楚性等对应章节；不存在修改时不编造修改说明。
- **正式正文与内部分析、风险提示分文件**；用户确认文字后才生成Word。

### 阶段5 | DOCX与提交前检查（仅当用户提出导出Word）
- 用户未提出Word就交付纯正文。需要时使用 `assets/意见陈述书正文_空白模板.docx` 或用户指定的可编辑模板，按照 `references/oa_writing_style.md` 渲染、逐页目视检查并校对。
- 若同时要权利要求替换页、对照页，则分别生成独立文件并同步核对，不用只凭意见陈述书倒推权项文本。
- 可运行 `scripts/qa_docx.py` 做案件号、权项数和明显重复标点的机械初筛；**此脚本不能证明法律合规、修改有依据、正文一致性或真实页数**。
- 如缺少最终替换页、无法确认法条版本、技术效果缺乏依据，阻止标注“可提交”，并向用户说明缺项。

## 红线
1. 原权要 / 当前权要 / 候选稿 / 最终权要不能混用，尤其区分“原权5”和“当前有效权4”这种不同编号。
2. 对比文件D1—Dn不能只凭OA概述或其他案件的引用直接当成已经核实的原文公开。
3. 不能仅以“技术领域不同”“发明点不属于公知常识”“需要改造”当然认定有创造性。
4. 不把任何内部复盘案例视为已授权案例；同一案件的候选稿与最终答复文书不是同一份已核定终稿。
5. 重要阶段只有用户明确确认才推进；绝不自动提交国知局。
